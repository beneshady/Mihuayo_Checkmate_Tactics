# 渡河：单波地形与地图编辑实验

日期：2026-09-28。独立玩法实验，未合入主原型，不代表 US-007 的正式实现验收。

## 验证问题

- 水、山、树林能否改变通行、炮架、击退与敌方预告？
- 用户能否直接布置地图和双方棋子，快速完成“编辑 → 测试 → 调整”？
- 保留兵过河前横走、敌方待机、拆山不占位；本次不接入成长，只打一波。

## 启动与操作

在项目根目录运行：

```powershell
python -m http.server 8774 --bind 127.0.0.1 --directory web/experiments/terrain-wave
```

打开 <http://127.0.0.1:8774/>。也可直接打开同目录 `index.html`，但本机保存能否使用取决于浏览器对本地文件的限制。此实验不需要构建或外网依赖。

1. 点击 **编辑地图**。编辑模式使用正方格，敌方在上，我方在下，金色边框标出九宫。
2. 顶部地形按钮是持续画笔：选择后可以连续点不同格子；山上不能直接放棋子，地形也不会静默删除已有棋子。
3. **移动棋子**：先点棋子，再点空格。侧栏选择我方/敌方与棋种，再点空格添加。放置帅/将会移动现有同方首领，不生成第二枚。
4. **删除棋子**只删棋子，不改地形。支持撤销/重做和 Ctrl / ⌘ + Z、Shift + Z；Esc 取消移动中的选取。
5. 看侧栏校验结果，点击 **开始测试**。敌方先准备再冻结意图；这一移动不回写编辑原稿。
6. 测试中点 **返回编辑**修改测试前的原稿；**取消编辑**返回进入编辑之前的战局；**重开本场景**恢复自定义开局，而非默认地图。
7. **保存到本机**手动保存一份地图；刷新后进入编辑器，点击 **读取已保存地图**。读取本身也可撤销。存储仅使用本实验的 `terrain-wave.map.v1`，不读写主原型存储。未保存的编辑刷新后丢失，存储权限失败会在界面提示。

默认场景为一波战斗；下拉菜单另外提供推水、拆山、树林连锁练习。练习的首回合按示例布局开始，此后正常敌方准备；编辑后的地图一律从敌方准备阶段开始。

## 实验设定与边界

- 默认棋盘 9×9，河道第 5 行，桥在第 2、5、8 列。编辑器允许调整桥、水、山、树林与陆地的位置。
- 初始六枚我方：帅、车、炮、兵、弓兵、枪兵；敌方八枚。编辑器可调阵容，支持马；敌方最多八枚，控制条件预览复杂度。双方须各有一枚将帅，不允许叠子、山中出生、致死水格出生或九宫内放水。
- 双方兵及转职兵移动可前、左、右一步，不再限制过河前横走，仍不能后退。
- **调试预设**：我方车冲击 3 格并带震退，弓枪四方向射程 3 格；其他基础属性不变。没有升级按钮、技能点、成长选择或商店。炮默认无扩散；规则测试单独覆盖扩散与地形交互。
- 敌人避开致死水路；无更合适的合法移动可待机。暂不主动选择山为目标。冻结攻击若被推到对着山，可以命中山；山挡在路径中则不绕行。这些敌方选招细节是本实验选择，非正式平衡定案。
- 车打塌山后停前一格；推水击杀不追位。直接击杀水中的单位才按车规则占位。
- 2026-09-29：震退撞山时，受推棋子额外掉 1 血，山承受一次命中；双方同规则。棋子保持原位，即使山坍塌也不进入山格；撞死归推动者击杀，车不追位。直接击杀、无震退、树林闪避不触发碰撞；碰撞不再次判定闪避。棋子阻挡、越界或宫界仍无额外伤害。
- 树林闪避在实际攻击时判定，不在预览中抽取；命中/闪避都作为可能结果参与顺序预测。多目标独立判断。UI 只说“一定概率”，不显示具体概率。
- 主动致死移动先确认，不可撤销；普通安全移动可逆序撤销；实际攻击（包括闪避、冲击入水中断）锁定此前移动。此致死移动交互为实验默认，尚待用户体验反馈。
- 将帅实际阵亡才结束，双方同时阵亡时我方失败优先。只有一波；用户已确认第二波换地形，留待后续，不实现跨波继承。
- 不影响 `web/index.html`、`web/js/`、V1 文档或其他会话正在验收的版本。

## 玩法观察与下一步

### 2026-09-29 撞山补充验收

- 规则检查 32/32、交互检查 13/13 通过；覆盖撞死归属、完整山开裂、残山坍塌、不追位、直接击杀/闪避不触发碰撞，以及宫界等其他阻挡不额外伤害。
- 实际浏览器通过编辑器构造：我方车 `(3,4)`、敌方 2 血车 `(4,4)`、开裂山 `(5,4)`。预览明确显示普通伤害 1、撞山额外伤害 1、山坍塌、归我方击杀；确认后敌车消失、山变陆地、我方车留在 `(3,4)`、击杀数为 1，与预览一致。
- 浏览器无 warn/error；未保存测试地图，未操作用户已有对局。验收截图：`collision-preview.png`。仅独立实验生效，未整合主原型。

**实际观察**：默认地图可三回合通关：三枚兵系首轮清桥，炮移至 `(5,3)`，利用我方弓作为炮架依次击杀 `(5,8)` 的两名士及随后走入的敌将。全程不需拆山或推水，帅保持满血。

**设计判断**：推水提供“先造成伤害再改变位置”的明确反馈；拆山能同时改通路和炮架；树林会改变后续攻击条件。三者可产生战术差异，但当前默认布阵允许强力炮路线绕过大部分地形决策，不能据此宣称平衡或趣味性已验证。

**待用户试玩**：利用编辑器调整中路山体、桥位、炮与首领位置，判断是否更常出现两种以上可行路线，以及树林的不确定性是否有趣。用户决定继续探索或正式采用后，再由主策划确定整合范围；本实验不自动覆盖主原型。
