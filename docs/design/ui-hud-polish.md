## HUD 原则

棋盘保持中央可读空间；把我方操作与敌方预告放在不同面板中，使玩家能在选棋与查看风险之间切换视线。移动直接落子、攻击预览后确认、撤销和回合确认均沿用现有事件。使用文字、框线和焦点强化颜色状态，不只靠颜色辨识。

## 区域与视觉预算

- 桌面（大于 900px）：顶部状态栏、左侧我方面板、中央棋盘、右侧预览/意图面板、底部行动栏。外边距 12px；左右面板内部可独立滚动。当前棋子始终排在左侧前部。
- 901–1100px：左右栏缩为 242px / 224px，单位行动信息换行。棋盘相机按固定俯视角投影高度与可用宽度适配，不截断四角。
- 900px 及以下：顶部、棋盘、图例、我方面板、预览/意图依次进入文档流；页面允许纵向滚动；固定底部两行按钮，正文预留其高度和安全区。
- 主界面 5 个持续区域（状态、我方、棋盘、研判、行动），至多 1 个当前有效弹窗。中部棋盤不被面板覆盖；敌棋悬停浮层仅相关时出现。提示条仍使用现有 1800ms 自动消失规则。
- 深蓝底、暖金主操作、红色我方圆形标志、蓝色敌方方形棋子。正文与次级文字分别使用 `#edf1f5`、`#a8b5c5`；禁用按钮保留可读文字与不可点击状态。
- 静态面板无入场动画；按钮颜色过渡 150ms，`prefers-reduced-motion` 时停用 CSS 动画与过渡。已有棋子的轻微摆动未在本次修改范围中。

## 元素与交互状态

| 状态 | 页面反馈 |
| --- | --- |
| 开局选择增益 | 三张卡片，标题、效果与按钮；窄屏改成三行；焦点在首个增益按钮 |
| 无棋子选中 | 当前棋子/预览显示下一步提示；执行/取消按既有条件禁用 |
| 已选中 | 左侧选中边框与内侧标记；列表声明 `aria-pressed`；显示模式、方向与等级 |
| 技能点不足/阶段禁止 | 原有禁用按钮及原因；成长区可展开，不自动购买 |
| 攻击可提交 | 底部提示核对伤害与风险；执行按钮按既有预览状态启用 |
| 非法操作/友伤 | 右侧原规则提示和友伤警示；保留既有非耗资源行为 |
| 结束回合确认 | 焦点先放“继续行动”；Tab 留在弹窗，Escape 取消 |
| 暂停 | Tab 留在弹窗，Escape 通过既有继续按钮恢复 |
| 整备/救援/结果 | 卡片与按钮可换行、弹窗可滚动；原规则禁用条件保留 |
| 布阵 | 保留现有入口与命令；现有原型布阵流程仍待玩法修复验收 |

输入顺序为顶栏 → 左侧当前操作/成长/名单 → 右侧意图 → 底部行动。单位列表可用 Enter/空格选择；选后重新定位到同一棋子的列表焦点。鼠标点选名单后，桌面左栏回到当前棋子；有效攻击预览生成后，桌面右栏回到预览，窄屏将预览滚入视野。按钮、折叠标题采用原生键盘行为。弹窗显示时背景设为 inert，关闭后归还焦点。模式与方向按钮的 active 状态同步为 `aria-pressed`。

## 无障碍与开放问题

本次采用可见焦点、关键按钮至少 44px、文字辅助颜色、弹窗焦点循环、可读提示和减少运动作为实现目标。这是本次假设，未承诺项目全量无障碍等级。

按照 `ux-review`：Accessibility: NOT ASSESSED — no committed tier（`design/accessibility-requirements.md` 缺失）。棋盘格子仍是 Canvas，键盘仅能操作 DOM 控件及名单，完整纯键盘对局、屏幕阅读器棋盘导航、手柄与多语言均为 TBD。不可把本次局部检查称为全量无障碍认证。

当前模式沿用原生按钮、列表点选、折叠区和确认弹窗；原项目无模式库，本次不创建额外框架。以后新增交互时再由主策划确定模式库范围。
