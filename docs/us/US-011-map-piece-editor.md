# US-011：地图与棋子编辑器

日期：2026-10-05；2026-10-06 更新。
状态：2026-10-06 S2 正式编辑器、多张草稿保存与关卡绑定开发完成、自测通过，待主策划接手验收；未作策划验收通过声明。

本轮实施入口：[地形与地图编辑器实施合同](../design/terrain-map-integration-2026-10-06.md)。冲突时以该合同为准；第一关地形及现行规则依赖 US-007 的 S1，编辑器属于 S2；不把战斗自动存档算作本 US 已实现。

## 1. 用户故事与目标

作为玩法设计者和试玩者，我希望直接点选地形、放置和移动双方棋子，并快速完成“编辑 → 测试 → 返回调整”，不需要修改代码来调试地图。

编辑器是调试工具，不是正式战斗中任意改局的能力。界面应让用户看清当前工具、选中棋子、地图错误和保存结果。

## 2. 范围与依赖

- 地形战斗规则由 [US-007](US-007-water-mountain-forest.md) 管理；本 US 只负责地图与棋子编辑、校验、测试入口和草稿保存，不重复定义伤害、碰撞、闪避、成长与战斗撤回。
- 正式整合时沿用 [V2.3 已确认规则](../design/gameplay-v2.3-confirmed.md) 和 [US-010](US-010-gameplay-v23.md) 的有效基线；不得把旧实验调试属性当作正式兵种属性。
- 现有参考：[单波地形实验说明](../../web/experiments/terrain-wave/README.md)，实现位于 `web/experiments/terrain-wave/`。该实现包含单波、车预设震退、弓枪射程 3 格等调试设定，不代表正式规则。
- 第一版编辑固定 9×9 棋盘的初始地形与双方初始棋子。提供独立测试局，不覆盖玩家正式对局、存档、队伍或收益。
- 支持多张命名草稿和手动指定第 N 关；不做地图路线/分支选关。增援时序与出生点不可编辑，必须显示并校验，不允许借编辑器修改其时间与兵种规则。

## 3. 编辑与易用性

### 3.1 棋盘与工具

- 编辑时采用易点选的正方格，标明我方在下、敌方在上、双方九宫以及列/行坐标；与试玩视角切换时不能改变格子对应关系。
- 面向用户统一显示第 1～9 列、第 1～9 行；不要把内部零基坐标直接混入操作说明。
- 地形工具：陆地、水、桥、完整山、开裂山、树林。桥在战斗中按陆地处理；编辑器可改桥位用于实验，不表示正式固定地图的桥可以被战斗破坏。
- 棋子工具：选择阵营、选择当前版本已支持的棋种、添加、移动、删除。未实现的兵种或职业不提供虚假可用入口。
- 地形和添加工具为持续画笔，点格即可重复应用；始终突出当前工具和阵营，并给出简短操作提示。
- 移动棋子采用“点棋子 → 点空格”。选中状态清楚可见，可取消选取；非法落点解释原因，不静默改到其他格。
- 不覆盖已有棋子、不叠子、不把山画到棋子脚下。删除工具只删除棋子，不改变地形。
- 放置同方将帅时移动已有将帅，不生成第二枚；删除将帅后允许继续编辑，但在补齐之前不能开始测试。
- 支持逐步撤销和重做。新编辑清空重做分支；无可撤销/重做步骤时按钮禁用。提供按钮，不依赖快捷键才能操作。
- 保留 Ctrl/⌘+Z 撤销、Shift+Z 重做、Esc 取消棋子选取。快捷键不得干扰输入控件。
- 窄屏下工具和“开始测试”应可触达，棋盘格可准确点选；必要时允许明确的滚动，不以遮挡棋盘或缩小到难点选解决布局。

### 3.2 地图校验

- 双方必须各有一枚将帅；棋子不能越界、重叠、站在山上；将帅和士不能在己方九宫外出生。
- 兵、弓兵、枪兵、炮不能以致死水格为初始位置。编辑中可暂时存在待修正草稿，但必须提示并禁止启动测试。
- 将帅与士的入水规则尚未设计，九宫内不允许放水或山。
- 固定敌方出生格只能为陆地、桥或树林，不能放山或水；不因编辑自动把出生点挪走。
- 展示全部需要修正的问题及对应位置，不能只给“地图无效”。有效时明确提示可以测试。
- 本版编辑首波敌阵最多 8 枚（含唯一将），界面明确标注工具限制；不等于两波在场总人数上限，不得截掉正常增援。正式绑定额外校验我方固定帅位及 8 个安全布阵空位，详见实施合同。

## 4. 编辑、测试与原稿隔离

1. 从场景初始布局或当前自定义原稿进入编辑，不把测试后的死亡、位移或山体破坏自动当成新的初始地图。
2. “开始测试”先校验，再复制原稿创建新测试局；按该版本正常开局执行敌方准备与意图生成，不直接注入一个跳过准备的正式局。
3. 测试消耗行动、击杀或破坏地形不会修改原稿；测试结果不写入正式成长、金币或存档。
4. “返回编辑”打开测试前的原稿继续调整，不读取受损战场代替原稿。
5. “取消编辑”恢复进入编辑前的测试战局及其行动状态；不应用本次未采用的修改。
6. “重开本场景”恢复当前采用的自定义初始地图，而非默认地图；原有重开确认不得被绕过。
7. 编辑撤销与战斗撤回互相独立：前者编辑布局，后者遵守战斗规则，不能通过返回编辑为正式局撤销攻击。

## 5. 本机保存与关卡应用

- 支持新建、命名、保存、另存为和选择读取多张地图原稿，不把战斗中途状态保存成原稿，不静默覆盖其他地图。
- 刷新后可通过“读取已保存地图”恢复指定草稿；加载作为一次可撤销编辑。明确只保存在本浏览器当前站点，不是云存档。
- 读取损坏或不支持的保存内容时，显示错误且保留当前草稿；无保存内容时给予明确提示。
- 保存失败要告知用户未持久保存，不能显示成功。未保存修改刷新后可能丢失，界面须说明。
- 与正式游戏保存隔离；本 US 不授权清空旧存档或修改其他原型的保存内容。
- 草稿可以保留校验错误，但不能测试或应用。合法已保存草稿可“用于第 N 关”；已绑定时确认替换，绑定保存版本快照，后续草稿保存不会自动改正式关。
- 只在之后新进入该关时采用新绑定，不改变当前关、续局或当前关的重试快照。未配置后续关复用默认验证地图并提示。
- 正式跨关沿用战役队伍与经济，地图里的测试我方阵容不赠送/替换正式队友；我方仍在合法半场布阵。详细数据边界、入口和验证见实施合同第 4、6 节。

## 6. 不做事项与待定边界

- 不做随机地图生成、地图发布/分享、导入导出、云存档、批量拖拽涂画、分支选关或第二波出生点编辑；多张本机草稿和线性关号绑定已纳入本次。
- 不做任意调整 HP、SP、金币、等级、技能和职业的通用调试面板，不新增战斗规则。
- 不自动将实验整页覆盖到主原型；正式页面提供可见编辑器入口，独立编辑/测试状态，可编辑已实装棋种，测试完整两波流程。保留现有独立实验入口作为历史参考。
- 各关固定地形布局由主策划安排；本 US 提供编辑能力，不以一张可编辑地图代表关卡平衡已验证。

## 10. S2 开发交付与验证（2026-10-06）

实现：正常页面可见地图编辑器入口，独立 HTML 编辑页及独立测试 iframe；六地形、现有双方棋种/职业、添加移动删除、唯一将帅、撤销重做、输入框快捷键保护、全部布局错误列表。测试从真实准备流程开始，原稿和正式战局独立；返回编辑、取消恢复原测试、确认重开原自定义地图。保留旧实验，不覆盖实验规则。

`web/js/maps.js` 管理专用 `m0-map-library-v1` 本机多草稿：稳定 ID、名称去重、另存独立、读取可撤销、脏稿切换确认；允许保存非法稿但禁止测试/应用。失败、损坏或不兼容内容禁止静默覆盖。手动应用正整数关号保存版本快照，替换需确认；普通保存不更新绑定；新进入关卡才读新绑定，当前局与重试沿用旧快照。正式关只用地形/敌方模板，队伍与经济来自战役，固定帅位及合法部署保留。
