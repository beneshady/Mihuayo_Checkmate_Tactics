# M0 网页版交付说明（纯 HTML + three.js）

版本：web-v0.1｜交付日期：2026-09-15｜分支：`codex/web-gameplay-validation`

依据 `docs/design/m0-gdd.md`（web-v0.1）实现的浏览器可运行玩法验证版。未修改 GDD 任何既定玩法、数值与关卡配置；GDD 6.1 的初始位置、HP、金币、售价、部署点均按原文实现，未做平衡调整，故无需回写配置变更。

## 1. 启动方式

- **双击打开**：直接双击 `web/index.html`（经典脚本加载，无 ES Module、无 fetch、无外部图片，file:// 协议可用）。
- **或本地静态服务**：在仓库根目录任选一种（不强制）：
  - `npx serve web`
  - `python -m http.server -d web`
- 依赖已本地化：`web/vendor/three.min.js`（three.js r128 UMD 版，约 600KB，离线可用，无 CDN 依赖）。
- 技术栈仅网页三件套 + three.js 渲染库，无构建步骤、无框架、无游戏引擎。

## 2. 文件结构

| 文件 | 职责 |
| --- | --- |
| `web/index.html` | 页面骨架、HUD、面板与全部覆盖层（商店/结果/暂停/确认） |
| `web/js/rules.js` | 纯规则引擎（UMD：浏览器全局 `M0`，Node CommonJS 双端可用）。棋盘、走法、动作、意图、敌方结算、将死分析、波次、商店全部在此，与展示完全分离 |
| `web/js/app.js` | three.js 表现层：棋盘绘制、棋子、意图箭头、预览、动画队列、点选交互、输入锁、分帧分析调度 |
| `web/vendor/three.min.js` | three.js r128（本地依赖） |
| `tests/rules.test.cjs` | 规则测试，逐项对应 GDD 8.1 场景表 |
| `tests/find-playthrough.cjs` | beam search 自动搜索通关动作序列（马/炮两分支） |
| `tests/replays/horse.json` `cannon.json` | 生成的完整通关动作记录 |
| `tests/replay.test.cjs` | 回放测试：真实配置完整通关，逐步运行将死分析 |
| `tests/ui-headless.test.cjs` | 无头 UI 集成测试（见第 4 节） |
| `tests/static-check.cjs` | DOM id / rules API 静态一致性检查 |

运行测试（Node 18+，本机 Node v24.15.0）：

```
node tests/rules.test.cjs
node tests/replay.test.cjs        # 需先 node tests/find-playthrough.cjs 生成回放
node tests/static-check.cjs
node tests/ui-headless.test.cjs
```

注意：`node --test tests/` 在受限沙箱下会因子进程被拦截而失败（EPERM），直接单文件运行即可。

## 4. 无头 UI 测试的替代范围（如实说明）

本环境无法启动真实浏览器，`tests/ui-headless.test.cjs` 是对"浏览器试玩"的**部分自动化替代**，不是替代本身：

- 在 Node 中以桩 DOM / 桩 WebGLRenderer 加载**真实的** three.js、rules.js、app.js；
- 用与 app.js 一致的相机参数做真实射线数学，把两条通关回放通过**完整 UI 流程**打出来：点选棋子 → 目标预览（含路径/击杀/落点/威胁变化）→ 执行 → 结束回合（含未行动确认框）→ 商店购买与进入第二波 → 胜利结果页；
- 中途验证暂停/继续不产生额外行动、胜利后连续重开三次与暂停菜单重开均不残留单位/金币/回合。
- **未被覆盖**：真实 GPU 渲染效果、棋子文字字体回退、点击手感、动画节奏、不同分辨率/浏览器兼容。这些仍需人工浏览器试玩确认（见第 5 节），符合 GDD 8.3"不以代码检查通过代替实际试玩"的要求。

## 5. 人工浏览器试玩步骤（供测试/策划验收）

1. 双击 `web/index.html`，确认冷启动直接进入第一波，左侧面板可见 4 条敌方意图与执行序号。
2. 点选己方车（左下角），确认绿色移动点与红色攻击圈；点敌方卒 (0,3) 出现预览（路径、击杀 1、落点），点"执 行"后击杀入账（顶部击杀 +1、XP +1）。
3. 点"结束回合"（帅未行动会出现确认框），观察敌方按 1→4 序号依次行动，箭头逐步变淡。
4. 按马或炮分支的通关记录（`tests/replays/*.json`，坐标为 (x,y)，x 从左到右、y 从己方到底线）复现完整通关；或在商店自行选择购买。
5. 验证失败路径：故意把车调离、让帅暴露在敌炮/敌车路线上，观察"将军"红色横幅；送掉车并保持帅被锁定，观察"将死"与"主帅阵亡"两种不同失败文案。
6. 暂停/继续、切后台再回来，确认敌人不多走、不重复发奖；结果页与暂停菜单各重开一次。
7. 重点体验 GDD 第 1 节的三个体会目标与 5–10 分钟目标时长，记录节奏与难度问题。

## 6. 实现说明与假设（局部、低风险歧义的处理）

- **待机意图的展示**：GDD 4.4"没有合法动作则待机"。实现中待机敌人在意图列表与棋盘上仍占公开序号，显示为"待机（无合法动作）"与"休"角标，不产生动作。规则层以 `type:'standby'` 意图表示，执行时跳过。
- **敌方攻击目标被己方友军占据**：按 GDD 4.2"目的地被友军占据则取消"处理为原地取消（攻击友军非法）。
- **意图箭头与预测**：棋盘箭头颜色区分攻击（红）/移动（黄）；预测状态（命中/落空/取消/待机）用虚线、叉号、"空"、"休"角标与左侧面板文字同时表达；预览动作后箭头与面板即时切换为"执行后"的预测结果。预测、将死分析与实际结算复用 `rules.js` 中同一 `enemyPhase` 函数（GDD 4.3）。
- **非颜色阵营区分**：己方棋子为圆形棋面、敌方为方形棋面（另有红/蓝配色与"帅/将"文字差异），满足 GDD 7.1"不能只依赖颜色区分"。
- **分析调度**：将死分析以生成器分帧（12ms 时间片）运行，期间锁定输入并显示"分析局势…"；结果按局面缓存，重开后缓存与回调按代际（epoch）作废。
- **反向兼容**：`rules.js` 的 API 与旧 `m0-zyf` 工程 `rules/game.ts` 语义一致（除新增 standby 意图、`endTurn` 返回 `{state, effects}`、`submit` 附带 `action`、新增 `dangerNow`/`preview`），测试场景覆盖旧版全部用例。

## 7. 已知问题与限制

- 顶部横幅在隐藏后 `textContent` 残留旧文字（`display:none`，不可见，无功能影响）。
- 敌方阶段动画为顺序固定时长播片（逻辑与动画分离，动画只重放已结算的 Effect），节奏偏慢可后续调。
- 结束回合时"全部已行动则直接执行"的分支逻辑简单且经代码审查，但无头测试未单独覆盖该分支（回放中结束回合时帅常未行动，走的是确认框分支）。
- `m0-zyf/` 旧工程目录未做任何改动（未跟踪文件，保持原样）。
