## 1. 基线对照（移植的核心事实）

| 维度 | Cocos 现状 | 原型 v2.3 | 结论 |
| --- | --- | --- | --- |
| 棋盘 | 10×8 | 9×9，河 y=4，三桥 (1,4)/(4,4)/(7,4) | 全量对齐 |
| 地形 | plain/forest/water/road | land/water/bridge/mountain/cracked/forest；山被命中 2 次→cracked→land；林 30% 闪避 | 地形系统重写 |
| 宫区 | 无（road 近似） | 双方九宫（player 3-5,0-2 / enemy 3-5,6-8），帅固定 (4,0) | 新增九宫判定 |
| 数值 | HP 80~140、攻 35~50 | 帅 3（敌将 5）、车/炮/枪 2、其余 1；攻：炮/弓 2、其余 1 | **切换低数值体系**（经济/SP/碰撞扣 1 的地基） |
| 兵种 | 帅/车/马/炮/象/士/兵 | king/rook/horse/cannon/pawn/**archer/spearman**/advisor（8 种，无象）；rookRole: base/charge/pull | 新增弓/枪，象暂不出场 |
| 走法引擎 | moveSpecs 数据驱动（step/slide/jump） | 函数式 legalActions：兵「前进或过河横走」、弓「射程≥2 方向独立升级」、枪「贯穿 1..7 截断」、炮「移动≤3 + 隔 1 炮架 + 8 向溅射」、车「4 格移动/攻击合一」 | 走法引擎升级 v2（见决策 4） |
| 回合 | US-006 预告回合 | **同构**（prepareEnemy→generateIntents→enemyPhase；offset 相对位移、平移不追踪） | 回合框架保留 |
| 行动模型 | stamina 2 | ap/apLimit；车炮双额度（move/attack 可用性分离）；兵 ap=1+combo；敌方无额度 | 行动模型重写 |
| 阶段机 | generating/enemyPrep/playerTurn/enemyAttack/ended | deploy → commander(三选一) → player → enemy → …，回合 1..11 | 阶段机扩展 |
| 经济/成长 | 无 | 金币（普通 1/敌将 5）、SP、三选一（强健/血量/移动）、转职树、帅 buff、后备、商店 | 全新增 |
| 碰撞/位移/尸体 | offset 已预留并测试 | 冲锋/震退/牵引/强拉、A=1/B=2/C=1 同时结算、推尸、车撞山 车-1/目标-2 | 全新增（Core 为主） |
| 波次 | 无 | waveTwo 固定 6 格、占格阻挡、救援、第 11 回合终局 | 全新增 |
| 战役 | level-list 2 主线 + 3 演练 | 三关线性（关中/中原/江淮），第三关即终点；关卡=地图绑定+CONFIG 常量 | 战役框架对齐 |
| 存档 | 无 | localStorage：金币/队伍/成长/后备 + 入关/关卡快照 | Cocos `sys.localStorage` |
| 地图数据 | level JSON v1（网格数组） | `{version:1, tiles:{"x,y":type}, units:[{id,side,kind,x,y,rookRole?}]}` | 关卡格式升级 v2 |

## 2. 关键决策（默认推荐，可逐条推翻）

1. **数值体系对齐原型**：低数值是经济/成长/碰撞全部规则的地基；Cocos 旧数值、旧关卡 JSON、旧演练夹具全部按新体系重写。
2. **关卡格式升级 v2（实施修订：仅 v2，不双读）**：Cocos 关卡仍用 JSON 文件（对齐 `maps.js` schema + 战役 meta），`parseBattleState` **只认 v2**（读到 v1 直接报错，避免双格式长期共存）；5 个现存关卡已全量迁移 v2；九宫无水山、双方各一帅、帅/士在九宫、兵系不得在致死水格出生等校验照搬 `maps.js`。战役常量（桥位、波次表、九宫、11 回合上限）进 Core `CONFIG`（对齐 `R.CONFIG`）。（P0 实施时修订：v1 无现存消费方，双读只会延长迁移期。）
3. **兵种 roster 以原型 8 kind 为准**：象保留 def 不出场；士为我方固定装置（不占名额），敌士九宫斜走。
4. **走法引擎升级 v2**：保留数据驱动骨架，扩展 schema——条件方向（兵过河横走）、范围射程（弓≥2 / 枪贯穿 / 炮移动≤3）、方向独立升级字段（directionPaid/cannonMask）、截断语义（友军/尸体/山）。对拍以原型 `legalActions` 行为为准，不照抄其函数结构。
5. **移植策略：`rules.js` 为行为参考，`tests/*.cjs` 为对拍基准**：每阶段把原型对应测试移植进 `tests/core/` 双跑对照；原型调试钩子（`__M0_DEBUG__`）的等价能力在 Cocos 侧以 Core 纯函数直接可达。
6. **v2.3 §8 TBD 清单照搬不实施**：象技能、仕完整参数、马转职、山 HP 上限、拉 2 格、地图选关系统、旧存档迁移等不做；歧义退主策划。山「可破坏」按原型实做移植（合同标 TBD，交付标注边界）。
7. **地图编辑器（US-011）降级为可选尾阶段**：手写 JSON + 夹具回归够用。

## 3. 阶段计划

### P0 规则地基对齐（一切的前提，工作量最大）

- **数值与单位模型**：8 兵种 def + 运行时字段（hp/maxHp/attack/level/kills/sp/ap/apLimit/combo/fortify/directionPaid/cannonMask/rookRole/rook*Range/rookPush/commanderHealth/commanderMove/acted）。
- **走法引擎 v2**（决策 4）+ 各兵种语义：兵（前 1 格/过河横走，与攻击共 AP）、弓（四向≥2、友军尸体山截断、1 格盲区）、枪（四向贯穿 1..7、尸体前敌人照常命中）、炮（直线移动≤3 途中无阻挡、隔 1 炮架攻击、溅射 cannonMask）、车（4 格合一行动、击杀占格）、马（日字蹩腿）、士（九宫斜 1）。
- **地形规则**：fatalWater（兵系/炮途经水即死）、wet（车马禁攻击）、山阻挡+可破坏（命中计数→cracked→land）、桥按陆地、林 30% 闪避（`state.rng` LCG 与原型一致，预览标条件结果）。
- **行动模型**：ap/apLimit + 车炮双额度 + 兵 combo；resetTurn 对齐。
- **数据**：unit-defs.json、5 个关卡 JSON 迁 v2；`parseBattleState` 双版本兼容。
- **视图**：MapBuilder 新地形占位（山/桥/裂纹）+ 九宫框；威胁面板支持「条件结果」标注。
- **验收**：`tests/core` 全绿 + 原型 `terrain.test.cjs`/`legacy-rules.test.cjs` 核心用例移植对拍；US-006 预告回合在 9×9 新体系上完整可玩，零回归。

### P1 战役框架与经济

- 杀敌金币（killLedger/killValues 幂等防重）、敌将 5 金、过关一次性结算；Profile 存档（金币/队伍/职业/SP/后备）；主菜单 + 三关线性解锁 + 下一关；失败重试 = `levelSnapshot` 完整回滚（阵亡/尸体/转职/花点/后备/地形），可重选帅 buff 不叠加。
- 验收：两关连打经济与队伍延续正确；重试后本关成长归零（对拍 `v1-flow-browser` 流程用例）。

### P2 商店与布阵

- 关间商店（兵 3 / 车·马·炮 5，只卖基础版、可多购入后备）；上阵 ≤8 队友 + 帅 + 固定仕；开战前布阵（我方半场合法空格、帅/仕固定位）；阶段机加 deploy 阶段——布阵完成后才首次 prepareEnemy，不得提前锁定意图。
- 验收：购买→布阵→战斗→结算→商店闭环；后备保留成长、不获本关收益。

### P3 成长与转职

- SP：击杀 +1 等级 +1 SP、过关存活成长、牵引车过关 +1（幂等）；三选一升级（强健 fortify +1HP / 血量 / 移动 +1）；转职树（兵→弓/枪 2SP；车→冲锋/牵引 2SP 不可逆，转职赠送一次）；主帅 buff 三选一（health/move/rescue，跨波保留、跨关替换，排除帅/士）；兵 combo（2SP 永久 +1 AP 上限）。
- 验收：升级转职实际生效、重试回滚正确、SP 不可刷（对拍 `rules.test.cjs` 成长段）。

### P4 位移与碰撞（Core 重头）

- 冲锋车（移动/冲锋分离可转向、冲锋 1 格起每 SP+1 至 8、震退 1 SP 解锁推 1 格→碰撞）；牵引车（射程 3 起 SP+1 至 8、拉 1 格、贴身强拉双方各 -1）；碰撞合同（接触双方各 -1、三体 A=1/B=2/C=1 同时结算、山可挡不传递、车占腾空格、推尸规则）；推/拉入水死亡归推动者击杀。
- US-006 的 offset 意图机制直接复用于震退/牵引后的意图重算（攻击者位移语义已有 Core 单测）。
- 验收：原型三体碰撞、推尸、强拉用例逐条对拍（`rules.test.cjs` + `v23-contract.test.cjs`）。

### P5 尸体系统

- 尸体占格/挡路/别马腿/可作炮架、无 HP 不被普通伤害摧毁；我方陆地留尸、敌方消失、入水销毁、桥上保留；出生清尸例外并失去本关救援资格。
- 验收：尸体×炮架/马腿/冲锋/牵引交互逐条过（对拍 `legacy-rules.test.cjs` T 序列）。

### P6 波次与增援

- 固定波次表：第 5 回合末预告 6 敌出生格、第 6 回合（先救援）入场、7~11 重试、第 11 回合敌方结算后终局；占格阻挡（我方占者 -1、尸体清除入场、旧敌占格保守暂缓）；待入场常显标记；救援 buff 时机（第二波首次入场前一次）。
- 验收：按 v2.3 §4.1 时间表逐时点验收（对拍 `replay.test.cjs` 两波+救援回放）。

### P7 撤销与体验打磨

- 单步撤销（仅我方纯移动、产生伤害后锁定、完整恢复行动状态，不得借撤销绕过合一规则）；双重预览（`preview()` = 玩家动作后模拟 enemyPhase，revision 号防过期提交）；结束回合前确认框（预计主帅受击次数）；HUD/详情面板对齐原型；多机型适配。
- 验收：撤销与预览边界用例 + 双端分辨率检查。

### P8（可选）地图编辑器

- US-011 地图库/绑定校验移植（localStorage schema + validate(binding)）。默认暂缓。

## 5. 风险

1. **数值切换波及面大**：旧关卡/夹具/敌方预告计划全部按新数值重推——集中在 P0，靠夹具回归兜底。
2. **树林 30% 闪避 × 预告制**：预览标「条件结果」、结算才掷骰，威胁面板必须显式标注（如「树林 70%」），否则破坏「预览=实际」。
3. **走法引擎 v2 的回归面**：条件方向/范围射程会触碰现有 movement.ts 的 spec 语义——以对拍测试先行（移植用例 → 改引擎 → 双跑）。
4. **碰撞×意图×撤销三方交互**：震退/牵引改位后 offset 语义已验证；撤销快照须覆盖 corpses/intents/pendingSpawns——边界定为「仅我方纯移动可撤销」，与原型一致。
5. **原型实做与合同的偏差**（山可破坏、枪贯穿细节等）：以原型实做为移植基线、交付时标注与 v2.3 §8 TBD 的出入，由主策划裁决。
